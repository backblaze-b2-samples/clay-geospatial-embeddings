# Gated engine dependencies — NOT installed by `pnpm run setup` or CI.
#
# The base requirements.txt / requirements.lock keep the default verify path
# fast and hermetic. This heavier, riskier stack powers the geospatial + ML
# features (local Clay embeddings, the Imagery Library's GeoTIFF reads and
# thumbnails, similarity search, and the seed script). Install it explicitly:
#
#   services/api/.venv/bin/pip install -r services/api/requirements-ml.txt
#
# Every module that needs these imports them lazily, so without this file the
# app still boots, tests pass, and a job/search records an actionable
# "engine not installed" state instead of crashing.
#
# Headline capability uses Clay's OWN model (never a substitute):
#   https://github.com/Clay-foundation/model
# The PyPI wheel for claymodel==1.5.0 is mis-packaged (it installs the module
# files flat at the top of site-packages instead of under a `claymodel/`
# package dir), so `import claymodel` never resolves from it. Install from the
# source repo instead, which packages correctly. There is no `v1.5.0` git tag
# upstream; `main` currently declares `version = "1.5.0"` in its pyproject.toml,
# so it is the correct ref for this pin.
